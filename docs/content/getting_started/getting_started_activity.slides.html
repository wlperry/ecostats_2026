Part 2 · Build your project folder

Why a project folder?

Everything for this project lives in one folder, so every file path is relative to it — no more hunting for where a file went.

Create the folder structure

Make a new folder called pine_project. Inside it, create three sub-folders:

pine_project/
├── data/       ← your CSV and Excel files go here
├── scripts/    ← your .R code goes here
└── figures/    ← plots you save go here

Part 5 · Naming things well

Good names make code readable months later: be explicit (needle_length, not x2), never start with a number, and R is case-sensitive (length_mm ≠ Length_mm). Use lower_snake_case.

Part 8 · Vectors and data types

A vector is a series of values built with c(). A spreadsheet column is really just a vector.

▶ Run this in your Script:

Part 11 · Your first plot

Every ggplot is built from three pieces, joined with +: data, aes() (which columns map to x/y), and a geom (how to draw it).

▶ Run this — the simplest possible plot:

ggplot(pine_df, aes(x = wind, y = length_mm)) +
  geom_point()

⚠️ Watch out! The + sits at the end of a line, never the start.

Improve it one layer at a time

▶ Run this:

ggplot(pine_df, aes(x = wind, y = length_mm)) +
  geom_boxplot() +
  geom_jitter(width = 0.15, alpha = 0.6, color = "tomato") +
  labs(x = "Side of tree",
       y = "Needle length (mm)",
       title = "Needle length by wind exposure")

       width  = 3,
       height = 3,

⚠️ Watch out! ggsave() wants the filename first, then plot =. Always use dpi = 300.

Getting unstuck

When code breaks — and it will, that is normal:

  1. Read the error message out loud. R usually names the line and the problem.
  2. Check the usual suspects: did you run library(tidyverse)? Spelling? A missing ) or a + at the start of a line?
  3. ?function_name opens the built-in help page.
  4. Bring the exact error (copy-paste it) to class or office hours.

💡 Key idea: Every working scientist googles error messages daily. Getting stuck is not failing — it is the job.
