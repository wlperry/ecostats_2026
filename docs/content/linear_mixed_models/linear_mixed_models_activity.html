Activity: Linear Mixed Models

Random effects for nested data

Hands-on activity: refitting the sea urchin nested design with lme4::lmer(), choosing between the F-test and the Chi-square test when they disagree, reading variance components and the ICC, and proving the mixed model reproduces the traditional nested ANOVA.
Author

Bill Perry

In-class Activity 16: Linear Mixed Models

Today’s Objectives

  1. Tell a fixed effect from a random effect, and say why patch is random
  2. Write random-effects notation for nested and for crossed designs
  3. Fit a nested design as a mixed model with lme4::lmer()
  4. Run the F-test and the Chi-square test, and find that they disagree
  5. Choose between them, and defend the choice
  6. Read variance components and the ICC — information the nested ANOVA never gave you
  7. Run DHARMa diagnostics on a mixed model
  8. Prove lmer() reproduces aov(... + Error()) on a balanced design

Where this fits

In Activity 14 you analysed the sea urchin experiment with aov(algae ~ treat + Error(patch)). It gave the right answer — F = 2.72 on 3 and 12 df, p = 0.091 — by forcing the treatment to be tested against patch-to-patch variation.

Error() is the 1960s way to get the right denominator. It works, and it is brittle: it needs a balanced design, it cannot handle more than one grouping cleanly, and it tells you nothing about how much variation lives among patches.

A mixed model does the same job by naming patch as a random effect. Same question, better machinery — and one new piece of output that the nested ANOVA simply could not produce.

Fixed effect Random effect
What it is levels you chose levels drawn from a population
What you want the difference between them how much they vary
Here treat — the four densities patch — 16 bits of reef
Generalizes to these four densities reef patches in general

Random-effects notation:

Code Meaning
(1|group) a random intercept for each group
(slope|group) random intercept and random slope
(1|outer/inner) inner nested inside outer
(1|a) + (1|b) crossed, not nested

🧩 Block 1 — Fixed, random, and the model (after lecture Parts 1–3)

Sections 1–2: the data again, then the mixed model.

Section 1 · The sea urchin data, again

Written for you in the skeleton — run it and read it.

# ---- Libraries -------------------------------------------
library(janitor)
library(car)          # Anova()
library(lme4)         # lmer()
library(lmerTest)     # Satterthwaite df and p-values
library(emmeans)
library(performance)  # icc()
library(DHARMa)
library(tidyverse)

options(scipen = 999)
options(contrasts = c("contr.treatment", "contr.poly"))
# ---- 1 The sea urchin data, again ------------------------
u_df <- read_csv("data/andrew.csv") %>%
  clean_names() %>%
  mutate(
    treat = case_when(
      treat == "removal" ~ "0%",
      treat == "dens_66" ~ "33%",
      treat == "dens_33" ~ "66%",
      treat == "control" ~ "100%"
    ),
    treat = factor(treat, levels = c("0%", "33%", "66%", "100%")),
    patch = as_factor(patch)
  )

head(u_df)

Section 2 · Fit the mixed model

▶ Type this yourself:

# ---- 2 Fit the mixed model -------------------------------
mixed_model <- lmer(algae ~ treat + (1|patch), data = u_df,
                    control = lmerControl(calc.derivs = FALSE))

summary(mixed_model)

control = lmerControl(calc.derivs = FALSE) just suppresses a convergence check that is noisy on small datasets. It does not change the fit.

✏️ Q2: Find the Random effects block in the summary. There are two rows. What is each one, and what are the two numbers?

✏️ Q3: Why is patch the random effect and treat the fixed one? What would it mean to call patch fixed — what would you be claiming you wanted to know?

✏️ Q4: The summary reports Number of obs: 80, groups: patch, 16. Which of those two numbers is your real replication for testing treat?

🧩 Block 2 — Two tests that disagree (after lecture Parts 4–5)

Section 3: the same model, three tests, two different answers.

Section 3 · Two tests, two answers

Mixed models have an awkward problem: there is no single agreed way to count the denominator degrees of freedom. Different approximations give different p-values.

🔮 Predict first: Activity 14’s nested ANOVA gave p = 0.091. Will the mixed model’s F-test land near that, or somewhere else?

▶ Type this yourself — the F-test, with Kenward-Roger df:

# ---- 3 Two tests, two answers ----------------------------
Anova(mixed_model, type = 3, test.statistic = "F")

💡 Read the header R prints: “Kenward-Roger df”. car::Anova() has no ddf argument — it always uses Kenward-Roger when you ask for test.statistic = "F".

▶ Type this yourself — the Satterthwaite version, which is what lmerTest adds:

anova(mixed_model)

🔮 Predict first: before the next chunk — the Chi-square test is the same model again. Same answer, or different?

▶ Type this yourself — the Chi-square test:

Anova(mixed_model, type = 3, test.statistic = "Chisq")

✏️ Q5: Write down all three p-values. Two agree and one does not. Which is the odd one out, and which side of 0.05 does it fall on?

✏️ Q6: Chi-square = F × numerator df, and the Chi-square test assumes infinite denominator df. How many do you actually have? Is 12 infinite?

✏️ Q7: The rule of thumb: under ~100 observations or fewer than ~20 random-effect levels, use the F-test; over ~500 observations and more than ~50 levels, Chi-square is fine; in between, the F-test is safer. You have 80 observations and 16 patches. Which does the rule pick?

✏️ Q8: Here is the uncomfortable part. If you had run only the Chi-square test, you would have reported a significant treatment effect and never known. What does that tell you about running one test and stopping?

✏️ Q9: Could you defend the F-test to a reviewer who wanted the Chi-square? Write the one sentence you would say.

💡 Key idea: this is not a case of one test being broken. Both are legitimate approximations; they differ because one of them pretends you have more information than you do. When two defensible analyses straddle α = 0.05, the honest move is to say so and justify your choice — not to pick the one you like and delete the other.

Section 4 · Variance components — the new information

Everything so far has reproduced Activity 14. This is what Error(patch) could never give you.

🔮 Predict first: look back at Activity 14’s patch means — within the 0% treatment alone they ran from 2.2% to 62%. Before you run this: is more of the variation among patches, or among quadrats within a patch?

✏️ Q11: The ICC (intraclass correlation) is the share of total variance sitting among patches. What is yours? Say what it means in one plain sentence about this reef.

✏️ Q12: What would an ICC near zero mean about the patches? Near one?

✏️ Q13: The nested ANOVA in Activity 14 gave you a p-value and nothing else. Name the practical decision you could make with the ICC that you could not make with the p-value alone. (Think about designing the next experiment.)

✏️ Q15: You spent all of last week on models that refuse to predict impossible values. So what is this model assuming about algae that is not true, and what would you do about it? (You do not have to fix it today — name the fix.)

💡 Key idea: the mixed model fixed the error structure and left the distribution alone. Last week you fixed the distribution and left the error structure alone. Real data often needs both at once — that is a generalized linear mixed model, glmer(), and you now have both halves of it.
