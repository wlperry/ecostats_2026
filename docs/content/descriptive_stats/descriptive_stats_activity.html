How to use this worksheet

Work through each part in order, at your own pace. Type every line of code yourself into a plain R script — do not copy-paste. Blocks marked ▶ Run this are code you should type and execute. Blocks marked ✏️ Your turn ask you to write, modify, or answer something. Boxes marked 🚀 If you finish early are optional bonus material.

Every grey r box below is code you type into an R script — not into the Console. Before you start: File → New File → R Script, and save it as 03_descriptive_stats.R in your project’s scripts/ folder. Then work down the worksheet, adding each block to the bottom of that one script, in order.

Type the # ── Part … header comment at the top of each block, too. Those comment lines are not decoration — they are how your script stays navigable, how you find your way back to a block that broke, and how I find your work when I read your script. A block with no header comment is a block I cannot place. In RStudio they also show up in the document outline (the ≡ button at the bottom-left of the editor) so you can jump straight to any part.

ImportantColumn names in pine_data.csv / pine_data.xlsx

Both files hold the same six columns, with exactly these names. Type them exactly as written — R is case-sensitive, and Needle_Length or needle_length will not work:

Column What it is
source_file the raw team file the row came from
team field team — one team = one tree
replicate needle number within a tree side (1-8)
side sun exposure — "shady" or "sunny"
needle_length_mm needle length, millimetres
needle_width_mm needle width, millimetres

After you read the file in, run names(pine_df) and check the names on your screen against this table before you write any other code.

Part 7 · Tidy group stats — group_by() + summarize()

📖 Read more: R4DS §3.5 — Groups.

You just wrote the same summarize() twice — once for shady_df, once for sunny_df. group_by() removes that duplication: it splits the whole data frame by a column, and summarize() then returns one row per group. No filter(), no two objects to keep in step.

▶ Run this:

# ── Part 7.1 · Tidy group stats ─────────────────────────────────────────
side_stats_df <- pine_df |>
  group_by(side) |>
  summarize(
    n       = sum(!is.na(needle_length_mm)),
    mean_mm = round(mean(needle_length_mm, na.rm = TRUE), 2),
    med_mm  = round(median(needle_length_mm, na.rm = TRUE), 2),
    sd_mm   = round(sd(needle_length_mm, na.rm = TRUE), 2),
    se_mm   = round(sd(needle_length_mm, na.rm = TRUE) / sqrt(n), 2)
  )

side_stats_df

⚠️ Watch out! Compute se_mm from the raw sd(), not from the sd_mm column above it — that one has already been rounded, and the SE would inherit the rounding error. Round only what you print.

Part 7c · The n you report is a choice

📖 Read more: Gotelli & Ellison Ch. 6 (Designing Successful Field Studies) on replication and pseudoreplication; Whitlock & Schluter Ch. 4 on what the standard error is an estimate of.

Your side summary said n = 32 per side. But we sampled only 4 trees — 8 needles from each. Counting needles as independent is the pseudoreplication from Getting Started.

▶ Run this — stage 1, collapse each tree to one number:

# ── Part 7c.1 · The `n` you report is a choice ──────────────────────────
team_means_df <- pine_df |>
  group_by(team, side) |>
  summarize(team_mean_mm = mean(needle_length_mm, na.rm = TRUE),
            .groups = "drop")

team_means_df

▶ Run this — stage 2, summarize those team means:

# ── Part 7c.2 · The `n` you report is a choice ──────────────────────────
side_correct_df <- team_means_df |>
  group_by(side) |>
  summarize(
    n_trees = sum(!is.na(team_mean_mm)),
    mean_mm = round(mean(team_mean_mm), 2),
    se_mm   = round(sd(team_mean_mm) / sqrt(n_trees), 2)

Part 7b · See it — boxplot with mean ± SE

📖 Read more: Whitlock & Schluter Ch. 2 (Displaying Data), and R4DS §10 — Exploratory data analysis.

Every number you computed today has a picture. This is the figure you will build for the rest of the term, so it is worth getting the layers straight.

▶ Run this:

# ── Part 7b.1 · See it — boxplot with mean ± SE ─────────────────────────
side_plot <- ggplot(pine_df, aes(x = side, y = needle_length_mm)) +

  # layer 1 — the spread of all 64 needles
  geom_boxplot(width = 0.5, fill = NA, outlier.shape = NA) +

  # layer 2 — each team's mean, faded, behind the summary
  geom_point(data = team_means_df,
             aes(y = team_mean_mm, color = team),
             position = position_dodge(width = 0.5),
             size = 3, alpha = 0.5) +

  # layer 3 — the mean and its standard error, on top
  stat_summary(fun = mean, geom = "point", size = 3) +
  stat_summary(fun.data = mean_se, geom = "errorbar", width = 0.15) +

  labs(x = "Sun exposure",
       y = "Needle length (mm)",
       color = "Field team") +
  theme_bw()

side_plot

stat_summary() computes a statistic while plotting — you never have to build a summary table first. fun = mean draws the mean as a point; fun.data = mean_se draws the mean ± 1 standard error as an error bar.

Getting unstuck

When code breaks — and it will, that is normal:

  1. Read the error message out loud. R usually names the line and the problem.
  2. Check the usual suspects: did you run library(tidyverse)? Spelling? Did you forget na.rm = TRUE?
  3. ?function_name opens the built-in help page.
  4. Bring the exact error (copy-paste it) to class or office hours.

📖 Read more: R4DS §8 — Workflow: getting help.

💡 Key idea: Every working scientist googles error messages daily. Getting stuck is not failing — it is the job.
