Activity: GLM & Logistic Regression

Generalized linear models

Hands-on activity: what to do when the ANOVA assumptions fail on count data. Gaussian, Poisson, and negative binomial GLMs on the Galapagos island-biogeography data, then logistic regression on Polis et al.’s Uta lizard presence/absence data.
Author

Bill Perry

In-class Activity 15: Generalized Linear Models

Today’s Objectives

  1. Fit the week-9 ANOVA on count data and watch its assumptions fail
  2. Say what a GLM’s three components are — distribution, predictors, link function
  3. Check that a Gaussian GLM reproduces lm() exactly
  4. Fit a Poisson GLM, and find out why the obvious choice for counts still fails
  5. Measure overdispersion, and say what it does to your p-values
  6. Fit a negative binomial GLM and confirm it fixed the problem
  7. Run the same escalation on a continuous predictor, on your own
  8. Fit a logistic regression on a binary response and interpret an odds ratio

Where this fits

For the last three weeks every model has been a linear model — one-way ANOVA, factorial, nested. All of them assume the residuals are normal with constant variance. That is a fine assumption for body mass or algae cover.

It is a bad assumption for a count. A count is a whole number, it cannot go below zero, and its variance usually grows with its mean. Today is what you do instead.

A generalized linear model keeps the linear part and swaps out two things:

Component What it is Example
Random the response’s distribution Poisson for counts
Systematic the predictors size_cat, area
Link connects the mean to the predictors log for counts, logit for binary
Response looks like Family
continuous, symmetric gaussian — this is just lm()
counts poisson
counts, variance > mean negative binomial (glm.nb)
binary — present/absent binomial(link = "logit")
positive, continuous, skewed Gamma

Column What it is

# ---- 1 The data ------------------------------------------
g_df <- gala %>%
  clean_names() %>%
  rename(spp = species) %>%
  mutate(
    size_cat = case_when(
      area < 1               ~ "small",

🧩 Block 2 — Three families, one question (after lecture Parts 3–5)

Sections 3–5: Gaussian (the sanity check), Poisson (fails), negative binomial (works).

Section 3 · A Gaussian GLM is the same linear model

Before trusting glm() with an unfamiliar distribution, check that it reproduces the one you already know.

🔮 Predict first: a Gaussian GLM with an identity link is a linear model. Will the coefficients be identical to lm_model, or just similar?

▶ Type this yourself:

# ---- 3 A Gaussian GLM is the same linear model -----------
gauss_model <- glm(spp ~ size_cat, data = g_df,
                   family = gaussian(link = "identity"))

summary(gauss_model)

Anova(gauss_model, type = "III", test = "F")

✏️ Q7: Compare the coefficients and the size_cat p-value to section 2. Identical, or just close?

✏️ Q8: So if a Gaussian GLM is just lm() again, what is glm() actually adding? (What did you have to name in the glm() call that lm() never asked for?)

💡 Key idea: lm() is the special case of glm() where the family is Gaussian and the link is the identity. Everything that follows changes exactly those two arguments. You are not learning a new model — you are learning two knobs on the one you already have.

Section 4 · Poisson GLM — the obvious choice, and it fails

Poisson is the distribution for counts. It has only one parameter, which means its mean and its variance are forced to be the same number. Remember the ratio you computed in Q3.

🔮 Predict first: the Poisson distribution insists variance = mean. Your data’s ratio was over 100. Will the overdispersion check come back clean?

▶ Type this yourself:

# ---- 4 Poisson GLM - the obvious choice, and it fails ----
poiss_model <- glm(spp ~ size_cat, data = g_df,
                   family = poisson(link = "log"))

summary(poiss_model)

Anova(poiss_model, type = "III", test = "LR")

A Poisson GLM cannot use an F-test, so we use a likelihood ratio test instead — it compares the fit of the full model against a model without the predictor.

▶ Type this yourself:

check_overdispersion(poiss_model)

sim_poiss <- simulateResiduals(poiss_model, n = 1000)
plot(sim_poiss)
testDispersion(sim_poiss)

⚠️ Watch out! shapiro.test(residuals(poiss_model)) will run, and it will give you a number. The number is meaningless — normality of raw residuals is not a Poisson assumption. R will not stop you from running a test that does not apply. This is why you check the diagnostic that matches the model, not the one you remember.

✏️ Q9: Why can a Poisson GLM not use an F-test? (What does an F-test need in its denominator that this model never estimates?)

✏️ Q10: The dispersion ratio should be about 1. What did you get? Given Q3, is that a surprise?

✏️ Q11: Overdispersion makes standard errors too small, which makes test statistics too big. Write down the size_cat LR chi-square here — you will compare it to section 5’s.

✏️ Q12: Look at the DHARMa Q-Q plot. Is the problem subtle?

💡 Key idea: Poisson was the right instinct and still the wrong model. “It’s count data, so use Poisson” is not enough — Poisson makes a second, much stronger claim, that the variance equals the mean. Ecological counts almost never oblige, because real populations cluster.

Section 5 · Negative binomial — the one that works

The negative binomial adds a second parameter, theta, which lets the variance exceed the mean by however much it needs to.

▶ Type this yourself:

# ---- 5 Negative binomial - the one that works ------------
nb_model <- glm.nb(spp ~ size_cat, data = g_df)

summary(nb_model)

Anova(nb_model, type = "III", test = "LR")

▶ Type this yourself:

check_overdispersion(nb_model)

sim_nb <- simulateResiduals(nb_model, n = 1000)
plot(sim_nb)

AIC(poiss_model, nb_model)

▶ Type this yourself:

nb_emm <- emmeans(nb_model, ~ size_cat, type = "response")
nb_emm

pairs(nb_emm)

multcomp::cld(nb_emm, Letters = letters)

✏️ Q13: The NB dispersion ratio and its p-value — is the overdispersion gone?

✏️ Q14: Compare the size_cat LR chi-square to the Poisson one from Q11. By what factor was the Poisson version inflated?

✏️ Q15: The AIC gap between the two models is enormous. Same data, same predictor, same link — so where did all that fit come from?

✏️ Q16: type = "response" back-transforms the means from the log scale. Look at the confidence limits: why are they no longer symmetric around each mean?

✏️ Q17: Read the letter display. Are all three size categories distinguishable?

💡 Key idea: you fitted three models to one question and got three different p-values, all of them tiny. The number was never the problem. What changed across the three is whether you are entitled to it — and only the third model’s diagnostics say yes.

Section 7 · Logistic regression — a binary response

A count was one kind of non-normal response. A yes/no is another. Logistic regression models the probability of a 1, using the logit link to stretch probability (stuck between 0 and 1) onto a scale that runs from −∞ to +∞:

\[\log\left(\frac{\pi}{1-\pi}\right) = \beta_0 + \beta_1 x\]

Polis et al. (1998) recorded whether the lizard Uta was present on 19 islands in the Gulf of California, against each island’s perimeter-to-area ratio — a measure of how exposed the island’s shoreline is. These are the real data from the paper, as reproduced in Quinn & Keough Box 13.1.

Written for you in the skeleton — the "." missing-value codes need handling, and Peninsula has no paratio:

# ---- 7 Logistic regression - a binary response -----------
polis_df <- read_csv("data/polis.csv", na = c(".", "")) %>%
  clean_names() %>%
  drop_na(paratio, pa)

polis_df

count(polis_df, uta)

▶ Type this yourself:

ggplot(polis_df, aes(x = paratio, y = pa)) +
  geom_point()

🔮 Predict first: exposed shorelines are hard places to be a lizard. Will the slope be positive or negative?

▶ Type this yourself:

lizard_model <- glm(pa ~ paratio, data = polis_df,
                    family = binomial(link = "logit"))

summary(lizard_model)

▶ Type this yourself — the likelihood ratio test, against a model with no predictor:

null_model <- glm(pa ~ 1, data = polis_df, family = binomial(link = "logit"))

anova(null_model, lizard_model, test = "Chisq")

▶ Type this yourself — the odds ratio, three ways:

exp(coef(lizard_model))
exp(confint(lizard_model, "paratio"))

model_parameters(lizard_model, exponentiate = TRUE)

tidy(lizard_model, exponentiate = TRUE, conf.int = TRUE)

▶ Type this yourself — goodness of fit:

r2(lizard_model)

pR2(lizard_model)

hoslem.test(lizard_model$y, fitted(lizard_model), g = 10)

▶ Type this yourself — the fitted probability curve:

pred_df <- data.frame(
  paratio = seq(min(polis_df$paratio), max(polis_df$paratio), length.out = 100)
)

pred_df$prob <- predict(lizard_model, newdata = pred_df, type = "response")

ggplot() +
  geom_point(data = polis_df, aes(x = paratio, y = pa)) +
  geom_line(data = pred_df, aes(x = paratio, y = prob))

✏️ Q21: Report the slope and the odds ratio with its CI. Does the CI include 1, and why does that matter more than whether it includes 0?

✏️ Q22: Say what the odds ratio means about Uta and shoreline exposure — in lizards, not in log-odds. “For every one-unit increase in perimeter-to-area ratio, the odds of finding Uta …”

✏️ Q23: For the Hosmer–Lemeshow test you want a non-significant p-value. Why is that backwards from every other test you have run this semester?

✏️ Q24: r2() reports a pseudo-R². Why “pseudo” — what can’t you compute here that you could in a regression?

✏️ Q25: Look at your curve. At roughly what perimeter-to-area ratio is Uta a coin flip?

💡 Key idea: the link function is doing the work in both halves of today. A log link keeps predicted counts above zero; a logit link keeps predicted probabilities between 0 and 1. In both cases the linear part of the model is unchanged — you are still fitting a straight line, just on a scale where a straight line cannot predict something impossible.
