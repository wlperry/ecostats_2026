The same data, two file formats

Part 2 · The Five Wrangling Verbs

The Five Wrangling Verbs

Almost everything you do to a data frame is one of these five functions, chained with the pipe |>:

Function What it does
filter() keep rows matching a condition
select() keep columns by name
mutate() add or change a column
arrange() sort rows
summarize() collapse rows to a summary

All take a data frame as input and return a data frame — that’s what makes them chainable.

Note

✅ Key idea

summarize() is Describing Your Data’s whole topic.
Today: the other four, plus saving what you build.

Tip

Read a pipeline out loud

pine_csv_df |>
  filter(...) |>   # then
  select(...) |>   # then
  mutate(...) |>   # then
  arrange(...)     # then

Each |> reads as “then.”

AND vs. OR

  • A comma between conditions means AND
    • —every condition must be true for a row to be kept.
  • Use | between conditions for OR instead

Tip

📖 Why log-transform?

  • Many biological measurements are right-skewed
    • a log transform pulls extreme values in and can make a distribution more symmetric before you summarize or test it.
  • We’ll check whether it matters for our data in a later module
  • Know which log you are using. In R, log() is the natural log (ln, base e); log2() and log10() are the other two. Always say which one in your methods.

Part 2b · case_when() — Recoding and Binning

case_when() — Turning a Number into a Category

Note

🔮 Predict first: We’re about to bin needle_length_mm into "short" (< 13), "medium" (< 16), and "long". The first needle in the data is 18.44 mm. Which bin does it land in — and would that change if the cutoffs used <= instead of <?

pine_csv_df |>
  mutate(
    size_class = case_when(
      needle_length_mm < 13 ~ "short",
      needle_length_mm < 16 ~ "medium",
      TRUE           ~ "long"
    )
  ) |>
  count(size_class)
# A tibble: 3 × 2
  size_class     n
  <chr>      <int>
1 long          21
2 medium        25
3 short         18
Note

✅ Key idea

case_when() checks conditions top to bottom and uses the first one that’s TRUE.
Once a row matches needle_length_mm < 13, R never even looks at the later conditions for that row.

📖 R4DS §12.5 — if_else() and case_when()

case_when() — Always End With TRUE ~

# What happens if we forget the catch-all?
pine_csv_df |>
  mutate(
    size_class = case_when(
      needle_length_mm < 13 ~ "short",
      needle_length_mm < 16 ~ "medium"
      # no TRUE ~ ... here
    )
  ) |>
  count(size_class)
# A tibble: 3 × 2
  size_class     n
  <chr>      <int>
1 medium        25
2 short         18
3 <NA>          21
Warning

⚠️ Watch out!

Drop the TRUE ~ "long" line and all 21 “long” needles silently become NA instead of erroring. case_when() never warns you — always finish with a TRUE ~ ... catch-all, even when you’re sure you’ve covered every case.

case_when() — Recoding Categories, Not Just Numbers

# Give each field team a short code
pine_csv_df |>
  mutate(
    team_code = case_when(
      team == "botany"     ~ "BOT",
      team == "grace_jace" ~ "GRJ",
      team == "one"        ~ "ONE",
      team == "waterbugs"  ~ "WBG",
      TRUE                 ~ "UNK"
    )
  ) |>
  distinct(team, team_code)
# A tibble: 4 × 2
  team       team_code
  <chr>      <chr>    
1 grace_jace GRJ      
2 botany     BOT      
3 one        ONE      
4 waterbugs  WBG
Tip

🖐 Notice

case_when() isn’t just for numeric cutoffs — every condition on the left of a ~ can be any boolean test: ==, %in%, >, even combinations with & and |.

The "UNK" catch-all should never actually appear here — if it does, that’s your signal a team name was misspelled somewhere upstream.

The Full Pipeline

pine_wrangled_df <- pine_csv_df |>
  filter(needle_length_mm > 0) |>                 # drop impossible values
  select(team, side, needle_length_mm, needle_width_mm) |>  # keep what we need

Part 3 · A Duplicate-Row Problem

A Duplicate-Row Problem

Remember pseudoreplication from Getting Started — one tree standing in for many? Duplicate rows are the data-entry version of the same mistake: the same measurement counted twice inflates your sample size without adding real information.

needle_check_df <- read_csv("data/pine_needles_error.csv")

nrow(needle_check_df)
[1] 69
n_distinct(needle_check_df)
[1] 64
Important

Something’s wrong: nrow() and n_distinct() don’t match. Some rows are exact repeats.

Note

📖 New words

  • n_distinct() — counts how many unique rows exist
  • distinct() — returns the data with duplicate rows removed — use it deliberately, not reflexively
  • unique() — lists the distinct values in a single column; the fastest way to spot misspellings

unique() — what else is wrong in here?

Two values became six. shady, Shady, SHADY — R treats every one as a separate category. Any group_by() or count() you run right now is wrong.

Tip

This file also has stray spaces ("sunny ", " shady"). You don’t see them because read_csv() trims whitespace for you by default. Prove it to yourself:

Fixing names and text in one pipeline

needle_fixed_df <- needle_check_df |>
  clean_names() |>                 # Needle Length (mm) -> needle_length_mm
  distinct() |>                    # drop the repeated rows
  mutate(
    side = str_squish(str_to_lower(side_of_tree)),
    team = str_squish(str_to_lower(team_name))
  )

unique(needle_fixed_df$side)
[1] "sunny" "shady"
unique(needle_fixed_df$team)
[1] "grace_jace" "botany"     "water bugs" "waterbugs"  "one"
Warning

⚠️ Watch out!

str_to_lower() collapsed Waterbugs into waterbugs — but water bugs is still its own value. Lowercasing fixes case, not spelling. That last one needs case_when().

Tip

🖐 Field habit

Run unique() on every text column the first time you open a dataset. It takes seconds and it is how you find the problems that silently split your groups.

Numbers that aren’t numbers

class(needle_fixed_df$needle_length_mm)
[1] "character"
class(needle_fixed_df$needle_width_mm)
[1] "character"

Both imported as text, not numbers — somebody typed 17.73 mm in a cell, somebody used a comma decimal (13,98), and the missing values were written four different ways.

needle_final_df <- needle_fixed_df |>
  mutate(
    team = case_when(team == "water bugs" ~ "waterbugs",
                     TRUE                 ~ team),
    needle_length_mm = needle_length_mm |>
      str_remove(" mm") |>                    # drop the typed unit
      str_replace(",", ".") |>                # comma decimal -> point
      na_if("") |> na_if("NA") |>             # blank and literal "NA"
      as.numeric(),
    needle_width_mm = needle_width_mm |>
      na_if("") |> na_if("na") |> na_if(".") |>   # three more ways to write "missing"
      as.numeric(),
    needle_length_mm = if_else(needle_length_mm == -999,
                               NA_real_, needle_length_mm)   # sentinel value
  )

class(needle_final_df$needle_length_mm)
[1] "numeric"
sum(is.na(needle_final_df$needle_length_mm))
[1] 3
sum(is.na(needle_final_df$needle_width_mm))
[1] 5
Important

⚠️ The trap: parse_number("13,98") returns 1398 — it reads the comma as a thousands separator and never warns you.

A 1398 mm pine needle is obvious if you look. Always summarize or plot a column right after you clean it.

Note

📖 New words

  • na_if(x, "") — turn a specific value into NA
  • -999 — a “sentinel” code some field sheets use for missing. R has no idea it means missing until you tell it.

Part 4 · Saving Your Work

The one-way street

Everything we did today runs in one direction:

data/     ← raw, read-only, never written to
   │  read_csv()
   ▼
scripts/  ← the cleaning code you just wrote
   │  write_csv()
   ▼
output/   ← everything R produces

The raw file is evidence. The script is the method. The output is a result you can always rebuild by re-running the method on the evidence.

Important

Never write into data/. If a script can overwrite the raw file, then one bad run destroys the only copy of what you actually measured — and no one can check your work.

Note

✅ Key idea

If you can’t reproduce a result from raw data + script, the problem is in the script — never in the raw file. Keeping data/ read-only is what makes that guarantee possible.

Tidy up before you save

needle_final_df still carries the wreckage of cleaning — the original messy columns and our fixed ones:

[5] "needle_length_mm" "needle_width_mm"  "side"             "team"

Nobody downstream needs team_name and team. Keep the columns you mean to keep, in the order you want them:

🖐 Field habit

select() right before write_csv() is the last checkpoint. A saved file with side and side_of_tree in it will confuse someone in three months — and that someone is usually you.

Note

select(new_name = old_name) renames while it selects — handy for dropping janitor’s replicate_number back to replicate.

write_csv() — the mirror image of read_csv()

write_csv(needle_out_df, "output/pine_needles_cleaned.csv")

Read from data/, write to output/. Same shape of call, opposite direction:

Reading Writing
read_csv("data/…") write_csv(df, "output/…")
file → data frame data frame → file
Warning

⚠️ Watch out!

write_csv() overwrites without asking — no warning, no undo. That is exactly why the target is output/ and never data/: re-running your script should be free, and it is only free if the thing it clobbers is something the script can rebuild.

Note

📖 Note the argument order

write_csv(df, path) — data frame first, then where to put it. read_csv(path) takes only the path. Getting these backwards is one of the most common errors of the term.

📖 R4DS §7.5 — Writing to a file

Naming your saved files

  • Name the file for what happened to it: pine_needles_cleaned.csv, not pine2.csv or final.csv
  • If a script produces several stages, number them: 01_cleaned.csv, 02_summarised.csv
  • Anyone re-running your script from scratch should get a byte-identical output file
Warning

⚠️ Watch out!

final.csv, final_v2.csv, final_FINAL.csv — version control by filename. This is exactly the mess a project folder with clear names and a re-runnable script is meant to prevent.

Tip

🖐 Try it yourself

Delete your output/ folder entirely, then re-run your script top to bottom.

Everything should come back. If it doesn’t, something important only exists in your console history — and that is a bug in your script.
