How to use this worksheet

How today runs: we work in stages. I lecture one part, then you stop and write the code for the matching worksheet part, then we go on to the next. Each part below says which lecture part it follows, so you can always find your place — and if you fall behind, the worksheet stands on its own.

Work through each part in order, at your own pace. Type every line of code yourself into a plain R script — do not copy-paste. Blocks marked ▶ Run this are code you should type and execute. Blocks marked ✏️ Your turn ask you to write, modify, or answer something. Boxes marked 🚀 If you finish early are optional bonus material.

Every grey r box below is code you type into an R script — not into the Console. Before you start: File → New File → R Script, and save it as 04_graphing_effectively.R in your project’s scripts/ folder. Then work down the worksheet, adding each block to the bottom of that one script, in order.

Type the # ── Part … header comment at the top of each block, too. Those comment lines are not decoration — they are how your script stays navigable, how you find your way back to a block that broke, and how I find your work when I read your script. A block with no header comment is a block I cannot place. In RStudio they also show up in the document outline (the ≡ button at the bottom-left of the editor) so you can jump straight to any part.

Part 3c · Axis limits with coord_cartesian()

Follows Lecture Part 2c — coord_cartesian().

📖 Read more: R4DS §11.4 — Scales.

ggplot picks the axis range from your data. That is fine while you explore, and wrong the moment a reader has to judge how big a difference is. Set the limits on purpose.

▶ Run this in your Script:

# ── Part 3c.1 · Axis limits with coord_cartesian() ──────────────────────
# Start the y-axis at zero so the difference is shown at its real size
ggplot(pine_df, aes(x = side, y = needle_length_mm, fill = side)) +
  geom_boxplot(alpha = 0.6, outlier.shape = NA) +
  labs(
    title = "Needle Length by Side of Tree",
    x = "Side of tree",
    y = "Needle length (mm)"
  ) +
  coord_cartesian(ylim = c(0, 25)) +
  theme_minimal() +
  theme(legend.position = "none")

▶ Run this — both axes at once, on two continuous variables:

# ── Part 3c.2 · Axis limits with coord_cartesian() ──────────────────────
pine_scatter_plot <- ggplot(pine_df, aes(x = needle_length_mm, y = needle_width_mm,
                                         color = side)) +
  geom_point(alpha = 0.6, size = 2) +
  labs(
    title = "Needle Width vs. Length",
    x = "Needle length (mm)",
    y = "Needle width (mm)",
    color = "Side"
  ) +
  coord_cartesian(xlim = c(5, 25), ylim = c(0.4, 1.8)) +
  theme_minimal()

pine_scatter_plot
Warning

⚠️ The trap we just saw on screen — use coord_cartesian(), not ylim()

ylim(14, 16) and scale_y_continuous(limits = c(14, 16)) filter your data before the geom draws it. Every row outside the range is dropped, and the median, quartiles, and whiskers are recomputed from what survives — behind a “removed rows” warning that is very easy to read past.

coord_cartesian() computes the statistics on all the data and then zooms the view. The boxes do not move.

The rule: coord_cartesian() to zoom, filter() when you actually mean to remove data — on purpose, in the data step, where you can see it.

Part 7b · A themes file you write once and source() forever

Follows Lecture Part 6 — themes.

📥 Download the themes file

This file defines three theme functions, each built for a different final printed size:

Function Built for Base font
theme_small() ~3 × 3 in — a journal panel 9 pt
theme_regular() ~7 × 7 in — a report figure 16 pt
theme_large() ~16 × 16 in — a poster 36 pt

All three give the same publication look: white background, black panel border, black axis lines and ticks, bold axis titles, no gridlines.

ImportantDo this once, now
  1. Click the download button above and save r_themes_for_3_sizes.R into your project folder — the same folder your .Rproj file is in, not inside scripts/.
  2. Open it in RStudio and run the whole file: Ctrl/Cmd + Shift + Enter (or click Source).
  3. Look at your Environment pane. theme_small, theme_regular, and theme_large are now listed under Functions. That is all running it does — it defines them.

▶ Run this — from now on, this one line replaces all of it:

# ── Part 7b.1 · Source the themes file ──────────────────────────────────
# Put this at the TOP of your script, with your library() lines
source("r_themes_for_3_sizes.R")

▶ Run this — use a theme like any other layer:

# ── Part 7b.2 · Use the themes ──────────────────────────────────────────
pine_theme_plot <- ggplot(pine_df, aes(x = side, y = needle_length_mm, fill = side)) +
  geom_boxplot(alpha = 0.6, outlier.shape = NA) +
  labs(
    title = "Needle Length by Side of Tree",
    x = "Side of tree",
    y = "Needle length (mm)"
  ) +
  coord_cartesian(ylim = c(0, 25)) +
  theme_small() +
  theme(legend.position = "none")

Note

✅ Why source() instead of copy-paste

source() runs that file top to bottom, exactly as if you had typed it. Change a margin in the themes file once and every figure in every script picks the change up the next time you run it. Copy-pasted theme code gives you fifteen slightly different themes and no way to fix them all.

Warning

⚠️ Watch out!

source() needs the path to be right. With the file in your project root and your .Rproj open, "r_themes_for_3_sizes.R" is enough. If you put it in scripts/, the line becomes source("scripts/r_themes_for_3_sizes.R").

# ── Part 7c.4 · A three-panel figure ────────────────────────────────────

  plot_annotation(tag_levels = "A")

combined_plot

Parentheses group plots exactly like arithmetic: (a + b) / c puts two panels on top and one across the bottom. plot_annotation(tag_levels = "A") tags them A, B, C — the labels a figure caption refers to.

Getting unstuck

When code breaks — and it will, that is normal:

  1. Read the error message out loud. R usually names the line and the problem.
  2. Check the usual suspects: did you run library(tidyverse)? Is color/fill inside aes() when it should be?
  3. ?function_name opens the built-in help page.
  4. Bring the exact error (copy-paste it) to class or office hours.

📖 Read more: R4DS §8 — Workflow: getting help.

💡 Key idea: Every working scientist googles error messages daily. Getting stuck is not failing — it is the job.
